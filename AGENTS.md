# AGENTS.md

C89 reimplementation of the Windows `cmd.exe` interpreter for Unix and Windows,
using only a POSIX.1 libc / Win32. All C sources live in the repository root;
`mcpp/` (entry wrapper) and `gradle/` (wrapper config) are the only
subdirectories.

Contributor-facing versions of these rules live in `CONTRIBUTING.md` (English)
and `CONTRIBUTING.zh_CN.md` (Simplified Chinese); conduct expectations are in
`CODE_OF_CONDUCT.md` / `CODE_OF_CONDUCT.zh_CN.md`.

## Non-negotiable constraints

- **Portability boundary.** Only `l*.c`, `l*.h`, `lw*.c`, and `lw*.h` may call
  POSIX or Win32 APIs. Every other translation unit may use only ISO C libc
  plus the `libcmd_*` interface declared in `glibcmd.h`; do not add
  `<unistd.h>`, `<dirent.h>`, `<sys/stat.h>`, `<windows.h>`, or similar headers
  to `b*.c`, `c*.c`, or `i*.c`. `glibcmd.h` is the only shared header that
  exposes platform types. Known violation: `bvol.c` calls POSIX `stat()`
  directly; migrate it to a libcmd wrapper when touching that file.
- **Supported hosts.** Linux, FreeBSD, OpenBSD, NetBSD, Haiku, Darwin/macOS,
  MSYS2, System V R4, other POSIX systems, and Windows. Do not rely on GNU or
  Linux-only extensions; keep platform differences in the l/lw layer or
  `lsysport.c`.
- **One function, one job.** Keep argument parsing, variable expansion, AST
  parsing, state changes, I/O, and command execution in separate helpers.
  Split multi-purpose functions rather than extending them.

## Build and verify

```sh
make -j$(nproc)                 # primary build: cmd.exe + COMMAND.COM
./cmd.exe /q /c "echo hello & cd /tmp & dir"
make clean
```

There is no test suite. Verify by building both binaries and exercising the
changed behavior manually, including `/c` strings and batch files.

- Both executables are built from the same `*.c` files. Only `cmain.c` reacts to
  `ENABLE_AUTOEXEC=1`, which adds the `COMMAND.COM` startup script handling.
- Generic/System V build: `sh tbuild.sh`. It defaults to `SYSV=1`, always
  compiles with `-DLIBCMD_NO_VSNPRINTF=1` (even on modern systems, to exercise
  the fallback formatter), and does not pass warning flags. Use
  `SYSV=0 sh tbuild.sh` to drop the System V shims.
- Other supported builds: CMake, Meson, `./gradlew build`, XMake, mcpp.
- Adding or removing a `.c` file requires updating the explicit source lists in
  `meson.build`, `cmd.vcxproj`, `COMMAND.vcxproj`, `cmd.cbp`, `COMMAND.cbp`,
  `cmd.dev`, `COMMAND.dev`, and the VS `.filters` files. Makefile, CMake,
  Gradle, XMake, and mcpp discover sources by glob.
- mcpp compiles shared sources once, so `COMMAND.COM` uses
  `mcpp/cmain_command.c`, which includes `../cmain.c`. Do not add a second
  `main` file for mcpp.

## Architecture

- `cmain.c` parses switches into `cmd_context_t` (state in `ccontext.h`), then
  runs a `/c` string, a batch file, or the interactive REPL.
- Execution flow: `cinterp.c:cmd_run_line` (echo, `@`, `::`, DOSKEY, `%VAR%`
  expansion) -> `cparser.c:cmd_parse` (AST for `&`, `&&`, `||`, `|`, `(...)`)
  -> `cmd_exec_node` -> `cdispatch.c:cmd_dispatch` (builtin table, otherwise an
  external command). `credir.c` applies/restores redirections.
- Builtins are one file each (`b*.c`) with a `builtin_*` function; register new
  ones in `builtin_table` in `cdispatch.c`.
- `glibcmd.h` is the libcmd portability API. Code outside the l/lw layer must
  call these wrappers, never raw POSIX/Win32 functions. Each operation has a
  POSIX implementation in `l*.c` and a Windows one in `lw*.c` (e.g. `lfs.c` /
  `lwfs.c`). Both are compiled on every platform and the inapplicable one is
  compiled out by `#if defined(_WIN32) || defined(_WIN64) || defined(_MSC_VER)`.
  Update `glibcmd.h` and both implementations together.
- Each `l*.c` / `lw*.c` file must include `glibcmd.h` first (it sets POSIX
  feature-test macros before system headers) and must remain non-empty when
  compiled out, because System V C rejects empty translation units.

## Source conventions

- Stay C89-clean (`-std=c89 -pedantic`): no `//` comments, no `#pragma once`,
  use include guards. Keep `-Wall -Wextra -Wpedantic` clean.
- File names follow 8.3 (max 12 characters) with the prefix scheme documented
  in `CONTRIBUTING.md` (`b` builtin, `c` cmd core, `g` shared header, `i`
  i18n, `l` libcmd, `t` tools, `o` overview). `./tlint.sh <file>` checks
  filename length, trailing newline, and ASCII; it accepts one file per
  invocation.
- Sources are ASCII. UI text belongs in `i<lang>.txt`; `i<lang>.h` and
  `ilanguages.h` are generated by `./ti18ngen.sh` and must not be edited.
  New messages require an ID in `imessages.h` and entries in all four
  `i<lang>.txt` catalogs.
- Language selection checks `LANG` first, then `LC_MESSAGES`, `LC_ALL`,
  `LANGUAGE` (the README's listed order is wrong). Set `LANG=en_US.UTF-8` to
  force English output during tests.
- AutoRun scripts are read from `$CMD_PREFIX/etc/cmd/AutoRun` (default
  `/usr/local`); set `CMD_PREFIX` instead of installing when testing them.
- Release packaging: `./tpack.sh` regenerates i18n tables, lints the packaged
  file list, and writes the archives to the repository root.
